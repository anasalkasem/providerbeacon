# Automatic provider and Telegram details

Provider creation in the integration vault now starts an import after a valid website URL is entered. A preview shows the source logo and a real homepage screenshot. The provider name is suggested when the name has not been manually edited. Creation saves the imported logo, screenshot, public description, and Telegram contact with the draft. It does not publish the catalogue, verify the provider, change pricing, or access the provider API credentials.

Existing provider profiles have a **Get details** action. It fills missing public fields, preserves saved or manually edited fields, and offers explicit **Use this logo / Use this screenshot** buttons for replacements. Saving remains revision checked and audited.

Both staff and member group forms retrieve public Telegram preview information after a URL is pasted: name, description, avatar and an observed member/subscriber count when available. OpenAI may suggest topic and language from the actual name and description. Counts, names, photos and verification are never generated by the model. Counts retain their observation date and approximate/exact distinction. Other platforms continue to support manual entry.

## Sources and availability

- Website HTML is parsed without running scripts. JSON-LD logo declarations, logo image tags and site icons provide logo candidates. Social sharing banners are not used as logos or screenshots.
- Homepage screenshots use the [Thum.io URL API](https://www.thum.io/documentation/api/url), with `noanimate`, a 960px output width and a 750px viewport crop. No account or new Railway secret is required for the initial no-account allowance. Only the public homepage URL is sent. The app caps captures at 20 per UTC day (at most 620 in a 31-day month), below the [currently advertised 1,000 free monthly impressions](https://www.thum.io/). Upstream availability and limits still apply; a capture failure leaves the screenshot field editable.
- Telegram's public `t.me` page is the source; the app never joins a group, sends a message, or uses a user's Telegram session. Private, expired, protected and personal contact links may expose no usable group facts. No fabricated fallback is inserted.
- Source requests and image capture have deadlines and byte limits. A protected/challenge page does not supply the provider name. OpenAI is optional; deterministic fields continue working when AI is disabled or unavailable.

## Storage and boundaries

Migration `0026_link_metadata` adds a metadata cache, content-addressed image storage, and a nullable group metadata snapshot. Images are saved in MySQL, so they survive Railway container redeployments without adding a volume. Website cache entries last seven days when complete; Telegram entries last one hour. Partial results are retried after five minutes. Public visitors load cached images from ProviderBeacon, not the screenshot service or Telegram CDN. The frontend shows the capture/observation date.

Clients receive a source-bound metadata key. Creation/editing resolves that key on the server; clients cannot submit fabricated counts or substitute metadata from a different URL. Saved group metadata survives text edits and is cleared when the group URL changes. Approval still requires the existing staff review.

Preview requests require provider write permission, group review permission, or a signed-in member as appropriate. Staff mutations accept only the canonical or known `www` origin. Member mutations retain their existing origin checks. Shared database quotas limit each actor to 20 previews/hour, uncached source imports to 300/day, and screenshot captures to 20/day. Concurrent imports of the same URL in one process share a request.

All outbound fetches require HTTPS, reject credentials and private/reserved IPs, pin the validated DNS address to the TLS connection, validate the original TLS hostname, and repeat validation for redirects. Cookies and API keys are never forwarded. SVG imports are reduced to an artwork-only allowlist; executable content and external resources are removed. Media responses use `nosniff`, a sandboxed CSP, immutable hashes and same-site resource policy.

Cleanup removes old abandoned previews and images after at least 30 days, while retaining images referenced by provider profiles, groups or retained previews. Privacy text explains the source and processing services in all five locales.

## Verification

Regression coverage includes real form events with delayed/out-of-order responses, manual edits and clearing fields, private-link fallbacks, provider creation payloads, source binding, SVG attacks, private DNS/redirects, oversized responses, permissions/origins, database persistence, review state, media response headers and garbage collection. MySQL acceptance runs only against the isolated CI database, never production.
