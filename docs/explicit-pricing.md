# Explicit service pricing

Service prices have an amount, supported ISO currency, sale unit (`per_1000`, `per_item`, or `package`) and package contents where applicable. These fields describe reviewed pricing; they are never inferred from a provider name, service title, balance example or generic homepage.

`sourceRate` retains the exact API rate independently of the four-decimal review amount. The whitelisted source JSON also preserves the provider's currency and unit claims. Unknown claims remain unconfirmed. Confirmation requires service-specific HTTPS evidence, a supported currency/unit and package contents for packages. Eligibility review and approval/publication remain separate permissions and actions.

The additive migration retains the physical decimal column named `pricePerThousandUsd` for compatibility, but application code and API responses call it `priceAmount`. Existing explicit USD/per-1,000 confirmations are preserved; unconfirmed records receive no currency or unit. Original API rates are backfilled only from retained API responses. Historical snapshots without their original pricing basis remain labeled legacy; current metadata is never applied retrospectively.

An unchanged source hash and account currency preserve manual corrections, pricing and approval. A real source change returns the service to review and clears full pricing confirmation and sale-unit metadata. An explicitly confirmed account currency is retained. Already-staged rows from the previous release are rebuilt from their retained source before import. Processing remains bounded to 100 rows per transaction. The existing outlier ceiling of 100,000 and quarantine workflow remain in force; this release does not reinterpret outliers as package prices.

The owner confirmed USD for the existing JustAnotherPanel API account. Migration 0012 records that fact in the matching integration and its API services, with an audit entry. `sourceCurrency` accompanies `sourceRate` independently of an operator's edited display amount/currency. Future imports and source price snapshots retain the account currency. Existing historical snapshots and reviewed conversions are not relabeled. Public API listings display the exact rate with USD and support the USD filter, while their sale unit remains unknown. Currency confirmation alone does not enable quantity totals, price ranking, approval or quality verification. Other integrations have no default currency.

Public price sorting requires a single currency and a per-item or per-1,000 unit, enforced by the API. The query uses keyset pagination and ranks API listings by their original rate rather than the four-decimal review amount. Decimal cursors retain precision between pages. Each response remains bounded to 25 rows by default (50 maximum). This catalogue sort does not perform exchange-rate conversion; the comparison tool can show dated converted estimates alongside each offer's actual basis. A lowest-price badge requires the same currency, unit, platform, category and specified target market. Packages are displayed with their contents and receive no automatic cheapest ranking.

The classifier recognizes explicit popup/iPhone-device website traffic. On synchronization, it repairs only previously unknown Website-traffic destinations still pending review, with the existing audit trail. Reviewed classifications are preserved on unchanged source records. Classification is not an eligibility determination.

Validation covers currency/unit confirmation, package scope, exact decimal totals, mixed comparison rendering, optimistic-lock conflicts, API permissions, source changes, database pagination and a 100,000-row performance fixture. Full quality approval remains separate from publishing an explicitly opted-in source catalogue.

## Confirming original API units

Migration 0013 adds nullable source-unit evidence fields and does not confirm any existing service. `admin.services.confirmSourcePricing` requires `services.review`, a batch of 1–50 unique IDs with current revisions, an explicit unit, a service-specific HTTPS evidence URL, a reason, and an acknowledgement for every selected service. Packages also require their contents. The action locks providers and services in the same order as imports, updates all selected records atomically, records before/after values with the actor/IP, and invalidates catalogue caches. Revocation removes only source-unit evidence. Neither action changes provider verification, editorial prices, quality review or publication status.

The public calculator accepts a whole positive quantity, checks each offer's minimum and maximum, and calculates per-item or per-1,000 totals with decimal-string arithmetic. Packages retain their defined price/scope. Unknown units have no quantity total. Quick quantity buttons calculate only the current bounded page; changing quantity triggers a server filter only when the matching-quantity checkbox is enabled. No provider API call happens in the visitor request. Price sorting requires confirmed units, and comparison cannot label a lowest price across different currencies, units, platforms, categories, target markets or refill terms.

A unit confirmation is tied to the retained service ID, name, category, type, unit/currency claims, account currency and endpoint. Ordinary rate and order-limit changes preserve the unit and use the new exact rate in source price history. A change to the service's meaning or account revokes the confirmation. Package limit changes also revoke confirmation because they can change the package scope. These rules preserve evidence without silently approving new service definitions.

The JustAnotherPanel account currency is USD. Its public API schema does not establish the sale unit for every service. No universal per-1,000 unit is assigned: a reviewer must inspect the relevant provider rate list and explicitly confirm the applicable service group, keeping packages and exceptions separate.

## Automatic pricing evidence and public presentation

The sync worker reads the authenticated account's supported ISO currency, then prefers explicit service-level currency and unit fields. It never derives currency from a flag, provider country, dollar symbol, example balance or language model guess. Account balances and credentials are excluded from pricing snapshots.

For clean HTTPS `/api/v2` integrations, a public `/services` table can establish per-1,000 pricing for individually matched `Default` quantity services. Foollo's observed canonical path is `/en/services`. An inert HTML parser requires ID, Service and Rate per 1000 columns; both the numeric service ID and normalized name must match the authenticated catalogue. Duplicate identities, conflicting headings, nested description tables, unsupported units, invalid limits, packages, subscriptions and one-off `1–1` offers do not qualify. Public prices are never substituted for authenticated account rates. The earlier bounded smmpanelone heading adapter remains scoped to its verified endpoint and now excludes one-off offers too.

Public requests contain no credentials, follow no redirects, time out after 12 seconds and accept at most 2 MiB. Only the evidence URL and service-name hashes enter the resumable job snapshot. Fetch failures preserve catalogue availability without inventing a unit. Every sync re-evaluates automatic evidence; manual and blocked source-pricing decisions retain their existing protections. Pricing evidence does not approve service quality, publish a provider or confer a verification badge.

Migration 0023 schedules active credentialled integrations for a normal refresh without changing any currency, amount, sale unit or review decision. Server startup enqueues due integrations through the same locked, deduplicated scheduler used by GitHub Actions, so a deployment can refresh pricing without waiting for the next hourly trigger. Suspended providers and disabled integrations remain excluded by the existing queue guards.

Public price cards show one amount and one sale-unit caption. Missing metadata uses neutral styling and an expandable explanation naming the missing fact, with a provider link. A known EGP currency is never described as an unknown currency. Catalogue cards omit impossible quantity totals; the explicit comparison calculator retains a concise reason. Lowest comparable prices stay green and featured placements stay violet. Unknown units and package exceptions never gain fabricated totals or lowest-price badges. Cross-currency estimates in the comparison tool continue to use dated exchange-rate data; the catalogue's native-price sort retains its single-currency rule.
